# Measured runtime dependency set for the 2×2080Ti deployment.
#
# This file is *measured*, not aspirational: it lists exactly the distributions that a
# real serving run of the reference route loaded, pinned to the versions that were
# verified. It exists because the declared requirement files (`common.txt`, `cuda.txt`)
# cover every upstream feature, while this deployment only needs a subset.
#
# Reference route:
#   2x2080Ti/qwen27b/w8a16/mtp4-fp16kv-1x148K-text-only.env
#   (Qwen3.8-27B-FP8 + MTP, TP=2, text only, Rust frontend)
#
# How it was produced and how to re-check it:
#   1. bash tools/dep_audit.sh --out-dir /tmp/dep-audit -- <launcher args...>
#   2. python3 tools/dep_audit/check_minimal_set.py \
#        --report /tmp/dep-audit/report.json --requirements requirements/definitive-2080ti-measured.txt
#
# Scope and caveats:
#   * The Rust frontend is assumed. A `--frontend python` deployment additionally needs
#     the ASGI stack (uvicorn/uvloop and friends), which is deliberately not listed here.
#   * CUDA libraries appear as `nvidia-*` wheels because torch loads them from the pip
#     wheels; nothing is taken from /usr/local/cuda at runtime. The *tools* (nvcc, ptxas,
#     cmake, ninja) are NOT listed: they are not imported and the system CUDA toolkit
#     provides them, which is verified by a cold compile (`AOT reused=no`).
#   * `torchvision`/`torchaudio`/`torchcodec`/`tilelang`/`z3-solver` are listed because the
#     route does load them (via transformers, the multimodal registry, a native import and
#     torch's symbolic shapes). Dropping them means giving up the features that pull them.
#   * `pip` is intentionally not listed: it is a maintenance tool, not a runtime need.
